## Description

**Outcome:** Gen Story can now select between Nano Banana 2 (Gemini) and GPT Image 2.5 for scene image generation from the Generate, test-generation, and Review regenerate flows. Gemini generation supports both the Gemini Developer API and Vertex AI, while existing requests without a model continue to use the shared Nano Banana default.

**Why this matters:** Users can choose the provider that matches their credentials and generation needs. Vertex AI also provides a supported paid path when the Gemini API free tier cannot issue image-generation requests.

**Runtime/user impact:** The selected image model is remembered in the browser and propagated into queued generation requests. Missing provider credentials still produce the existing mock placeholders for that provider; no database migration is required.

**In scope**

- The API continues to use mock generation when the selected provider has no credentials.

## Decisions and Tradeoffs

### Decision: Route by an explicit shared model catalog

- **Decision:** Send the model ID in each generation request and select the provider from the shared catalog, defaulting missing IDs to Nano Banana 2.
- **Reason:** The existing queue and persistence contracts already carry arbitrary input JSON, so provider selection can be added without schema or migration work.
- **Gain:** Normal generation, test samples, retries, and regeneration use the same explicit model choice while legacy rows remain compatible.
- **Give up:** Adding another selectable model requires updating the catalog and its provider routing rule.
- **Rejected alternatives:** A single environment-selected provider would require process restarts and would not let users compare providers within one project.
- **Reversal cost:** Low; remove the selector and router while retaining the existing adapter contracts and default fallback.
- **Assumptions:** The configured Gemini model IDs and Vertex AI image-generation availability remain valid for the deployed credentials.

### Decision: Keep Vertex AI project selection repository-scoped

- **Decision:** The `pnpm gcloud` wrapper always targets `gen-story-496911` and rejects caller-supplied project overrides.
- **Reason:** Project-scoped operations must not mutate the operator's global gcloud project setting or accidentally target another project.
- **Gain:** Local setup commands are explicit and isolated to this repository's infrastructure project.
- **Give up:** Operators cannot use the wrapper for another project; they must use their normal gcloud command outside this repository workflow.
- **Rejected alternatives:** `gcloud config set project` would be shorter but changes shared machine state.
- **Reversal cost:** Low; change the wrapper and documentation, with no application data migration.
- **Assumptions:** Operators have Application Default Credentials and the required Vertex AI API enabled when using Vertex mode.

## Risks, Rollout, and Rollback

- **Known risks:** Real Gemini Developer API and Vertex AI image calls were not made during validation; the model IDs and credential configuration still require a live environment check.
- **Mitigations:** The adapter has focused response/storage tests, missing credentials use the existing mock path, and Vertex project selection is explicit and isolated.
- **Rollout:** Run the normal API/web revision. Configure `GEMINI_API_KEY` or Vertex ADC plus `GEMINI_USE_VERTEXAI=true` and `GOOGLE_CLOUD_PROJECT` when real Gemini generation is desired. No migration is required.
- **Rollback:** Revert feature commit `5027e3c` to remove selectable models and restore the prior single-provider behavior.
- **Breaking changes:** None to REST routes, persisted schemas, or legacy generation requests.
